## The problem

You get the root of a **perfect** binary tree (every level completely full), whose nodes have an extra `next` pointer, initially none. Point each `next` at the node to its right on the same level, or none for the last node of a level.

For the tree `[1, 2, 3, 4, 5, 6, 7]`: 2 → 3, 4 → 5 → 6 → 7, and 1, 3 and 7 point to nothing.

## The key question

> **Once a level is linked, what does it give you for the level below?**

A way to walk the level left to right without a queue. In a perfect tree every child's neighbour is then easy to name.

## Approach 1: Level by level with a queue

Walk the tree level by level with a queue, linking each node to the one taken before it.

<Viz client:visible approach="queue" />

<Complexity time="O(n)" space="O(w)">
**Time.** Each node is queued once: **O(n)**.

**Space.** The queue holds up to a whole level, about n/2 nodes at the bottom: **O(w)**.

**What it wastes:** the queue. The levels already linked can be walked by their next pointers instead.
</Complexity>

## Approach 2: Walk each level by its next links (optimal)

Start at the leftmost node of a level and follow next pointers across it. For each node, `left.next ← right`, and `right.next ← next.left` if it has a next. Then go down to the next level's leftmost node.

<Viz client:visible approach="links" />

<Complexity time="O(n)" space="O(1)">
**Time.** Each node is visited once as part of its level's walk: **O(n)**.

**Space.** Two pointers: **O(1)**.
</Complexity>

## Comparing the approaches

Race two approaches on the same input. Both share one clock that ticks once per operation, so the one doing extra work visibly falls behind.

<Compare client:visible />

| Approach | Time | Space | Idea |
|---|---|---|---|
| Level by level with a queue | O(n) | O(w) | Queue per level |
| Walk each level by its next links | **O(n)** | O(1) | The level above is the list |

Both approaches are O(n) time, so there's no growth chart: the difference is the extra memory.

## Common mistakes

- **Linking a right child to nothing when the parent has a next.** It links across to the next node's left child.
- **Starting a level from the wrong node.** Each level starts at the leftmost node, the previous leftmost's left child.
- **Using this trick on a tree that isn't perfect.** Missing children break `next.left`; see the general version.
