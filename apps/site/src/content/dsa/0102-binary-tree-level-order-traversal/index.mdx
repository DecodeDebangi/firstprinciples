## The problem

You get the `root` of a binary tree. Return its values level by level: a list per level, each ordered left to right.

For `[1, 2, 3, 4, null, 5, 6, null, 7]` the answer is `[[1], [2, 3], [4, 5, 6], [7]]`.

## The key question

> **What order do I need to visit the nodes in?**

Top to bottom, left to right: the order they were discovered. "Handle things in the order they arrived" is
exactly what a **queue** does.

## Approach 1: One walk per level

For depth 0, 1, 2, …, walk down from the root and collect the nodes at exactly that depth. Stop when a depth comes
back empty. The shaded nodes show what each walk had to pass through again.

<Viz client:visible approach="rewalk" />

<Complexity time="O(n · h)" space="O(h)">
**Time.** The walk for depth `d` passes every node above it again. Over `h` levels that's up to `n · h` visits:
**O(n²)** for a tree shaped like a chain.

**Space.** Recursion depth: **O(h)**.

**What it wastes:** the top of the tree is walked once for every level below it.
</Complexity>

## Approach 2: Queue, one level at a time (optimal)

Put the root in a queue. Repeatedly: note how many nodes are in the queue (that's one whole level), take exactly
that many from the front, record their values, and add their children to the back.

<Viz client:visible approach="bfs" />

<Complexity time="O(n)" space="O(w)">
**Time.** Every node enters and leaves the queue once: **O(n)**.

**Space.** The queue holds at most two partial levels: **O(w)**, the width of the widest level (up to about `n / 2`).
</Complexity>

## Comparing the approaches

Race two approaches on the same input. Both share one clock that ticks once per operation, so the one doing extra work visibly falls behind. Choose any pair, or type your own input.

## Common mistakes

- **Not fixing the level size first.** Read `length(queue)` *before* the inner loop; children added during it belong to the next level.
- **Using a plain array as a queue.** Removing from the front (`list.pop(0)` in Python, `shift()` in JavaScript) is O(n); use a real queue (`collections.deque`, Java's `ArrayDeque`).
- **Empty tree.** Return `[]`, not `[[]]`.
