## The problem

You get the root of a binary tree whose values can be negative. A **path** is any sequence of nodes connected by edges, each used at most once; it doesn't have to pass through the root. Return the largest sum of values along any path (with at least one node).

For the tree `[2, -6, 5, 3, 4, -1, 7]` the answer is `14`: 2 → 5 → 7, bending at 2 after skipping the −6 side.

## The key question

> **What does a node have to tell its parent, and what can it only check itself?**

A parent can extend a path through only one side of its child, so the child returns its best **one-sided** gain. The path that bends at a node, using both sides, can't be extended upward, so the node checks it against the best so far itself. That's the [bottom-up](/concepts/tree-recursion/) pattern from Diameter of Binary Tree, with values instead of edge counts.

## Approach 1: Try every node as the top of the path

For each node, measure the best path going down its left side and its right side (from scratch), skip a side worth less than 0, and add the node's value.

<Viz client:visible approach="every" />

<Complexity time="O(n²)" space="O(h)">
**Time.** Each node measures both of its subtrees again: **O(n²)** on a chain.

**Space.** The recursion: **O(h)**.

**What it wastes:** subtrees are measured again for every ancestor above them.
</Complexity>

## Approach 2: Return the best one-sided gain, track the best bend (optimal)

One bottom-up walk. Each call gets the best gain from each child (0 if that side is negative), updates the best with `node + left + right`, and returns `node + max(left, right)`.

<Viz client:visible approach="once" />

<Complexity time="O(n)" space="O(h)">
**Time.** One visit per node: **O(n)**.

**Space.** The recursion: **O(h)**.
</Complexity>

## Common mistakes

- **Returning the bending path to the parent.** A path can't go down both sides and then up; return only one side.
- **Starting best at 0.** If every value is negative, the answer is the largest single value, so start at −∞.
- **Not skipping negative sides.** A side worth less than 0 should count as 0: the path simply doesn't go there.
