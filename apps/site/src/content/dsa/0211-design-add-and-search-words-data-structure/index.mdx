## The problem

Build a word store with two operations:

- `addWord(word)` stores a word.
- `search(pattern)` says whether any stored word matches the pattern. The pattern can contain `.`, which matches any
  single letter; every other letter must match exactly, and the lengths must be equal.

For example, with `bad`, `bed`, `bid`, `mad` and `pat` stored, `.a.` matches `bad` (and `mad`, and `pat`), `b..`
matches `bad`, and `..e` matches nothing.

Below, `L` is the length of the pattern and `N` the number of stored words.

## The key question

> **How do I skip whole groups of words that can't match, even when some letters are wildcards?**

See [Tries](/concepts/tries/) for storing and walking words, and [Backtracking](/concepts/backtracking/) for trying a
choice and undoing it.

## Approach 1: Check every stored word

Compare the pattern with each word of the same length, letter by letter, treating `.` as a match for anything.

<Viz client:visible approach="list" />

<Complexity time="O(N · L)" space="O(N · L)">
**Time.** Every search may compare against all `N` words, up to `L` letters each: **O(N · L)**.

**Space.** The stored words: **O(N · L)**.

**What it wastes:** words that differ in their first letter are each rejected separately. A trie rejects them all at
once, since they live in a branch the search never enters.
</Complexity>

## Approach 2: A trie, trying every child at a dot

Store the words in a trie. To search, walk it with a recursive function `dfs(node, i)`: for a real letter, follow that
child if it exists; for a `.`, try every child, and return true as soon as one branch succeeds. At the end of the
pattern, the node must be marked as the end of a word.

<Viz client:visible approach="trie" />

<Complexity time="O(L) without dots" space="O(N · L)">
**Time.** With no dots, one step per letter: **O(L)**. Each dot can multiply the branches tried by up to 26, so a
pattern full of dots can visit the whole trie, O(N · L), no worse than approach 1. Branches stop as soon as a letter
doesn't fit, so real searches stay far below that.

**Space.** The trie, **O(N · L)** nodes at most, plus the recursion's [call stack](/concepts/recursion/), O(L).
</Complexity>

## Common mistakes

- **Treating `.` as "any number of letters".** It matches exactly one letter.
- **Stopping at the first child for a dot.** If that branch fails, the next child may still match.
- **Forgetting the end mark.** `ba.` must not match a stored `bake`.
