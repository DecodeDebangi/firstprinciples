## The problem

You get the head of a linked list of positive whole numbers. Between every pair of neighbouring nodes, insert a new
node holding their **greatest common divisor**: the biggest whole number that divides both of them exactly. Return
the head.

For example, `18 → 12 → 20` becomes `18 → 6 → 12 → 4 → 20`: the biggest number dividing both 18 and 12 is 6, and
for 12 and 20 it's 4. A list with one node stays as it is.

## The key question

> **How fast can I find the greatest common divisor of two numbers?**

The linked-list part is a simple insertion walk: for each pair, link a new node in between, then move past it.
What decides the speed is the divisor calculation, done once per pair.

## Approach 1: Find each GCD by counting down

Start at the smaller of the two numbers, which is the biggest a divisor could be, and count down until a number
divides both exactly. That's guaranteed to stop by 1, which divides everything.

<Complexity time="O(n · m)" space="O(1)">
**Time.** For values up to `m`, one GCD can take up to `m` tries, as for 997 and 998 which share no divisor except
1. With `n` nodes there are `n − 1` pairs: **O(n · m)**.

**Space.** Each new node is part of the answer; apart from those, a few variables: **O(1)**.

**What it wastes:** it tries hundreds of numbers that can't possibly divide both.
</Complexity>

## Approach 2: Euclid's algorithm (optimal)

A number that divides both `a` and `b` also divides the remainder `a % b`, because the remainder is `a` minus a
multiple of `b`. The reverse is true too. So the pair `(b, a % b)` has exactly the same common divisors as `(a, b)`,
and the same greatest one, but its numbers are smaller. Keep replacing until the remainder is 0; the other number is
the answer:

`gcd(12, 20) = gcd(20, 12) = gcd(12, 8) = gcd(8, 4) = gcd(4, 0) = 4`.

This is **Euclid's algorithm**, over 2,000 years old and still the standard way.

<Viz client:visible approach="euclidWay" />

<Complexity time="O(n · log m)" space="O(1)">
**Time.** Every two steps of Euclid's algorithm at least halve the larger number, so a GCD takes **O(log m)**
steps. With `n − 1` pairs: **O(n · log m)**.

**Space.** A few variables besides the new nodes: **O(1)**.
</Complexity>

## Common mistakes

- **Moving onto the new node.** After inserting between `curr` and its next, move `curr` to `node.next`, the old
  next. Stepping onto the new node would insert another node next to it, forever.
- **Linking in the wrong order.** Set `node.next ← curr.next` before `curr.next ← node`, or the rest of the list is
  lost.
- **Starting the count-down at the larger value.** The divisor can't be bigger than the smaller number.
