## The problem

You get the root of a binary tree. Return the length, in edges, of the longest path where every node has the same value. The path doesn't have to pass through the root.

For the tree `[5, 4, 5, 4, 4, null, 5, null, null, null, 4]` the answer is `3`: the path 4 → 4 → 4 → 4 through the left side, bending at the first 4.

## The key question

> **What should each node tell its parent?**

The longest same-value arm going straight down from it. The parent can extend it by one edge only if their values match. It's [Diameter of Binary Tree](/dsa/diameter-of-binary-tree/) with that one extra rule.

## Approach 1: Measure both arms from every node

For each node, measure how far its value continues down each side, and add the two.

<Viz client:visible approach="every" />

<Complexity time="O(n²)" space="O(h)">
**Time.** Arms are re-measured from every node above them: **O(n²)** for a chain of equal values.

**Space.** The recursion: **O(h)**.

**What it wastes:** each arm is measured again by every ancestor with the same value.
</Complexity>

## Approach 2: Return one arm, track the best path (optimal)

Bottom-up, each node gets its children's arms, extends an arm by 1 only into a child with the same value (otherwise it's 0), records left + right as a candidate, and returns the longer arm.

<Viz client:visible approach="once" />

<Complexity time="O(n)" space="O(h)">
**Time.** One visit per node: **O(n)**.

**Space.** The recursion: **O(h)**.
</Complexity>

## Comparing the approaches

Race two approaches on the same input. Both share one clock that ticks once per operation, so the one doing extra work visibly falls behind.

<Compare client:visible />

| Approach | Time | Space | Idea |
|---|---|---|---|
| Measure both arms from every node | O(n²) | O(h) | Re-measure per node |
| Return one arm, track the best path | **O(n)** | O(h) | Return one arm, check both |

## Common mistakes

- **Counting nodes instead of edges.** A single node is a path of length 0.
- **Returning both arms to the parent.** A path can't come up from both sides and continue.
- **Extending into a child with a different value.** The arm resets to 0 there.
