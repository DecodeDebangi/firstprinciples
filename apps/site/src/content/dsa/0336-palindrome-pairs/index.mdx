## The problem

You get a list of different words. Return every ordered pair of positions `(i, j)`, with i ≠ j, such that `words[i] + words[j]` reads the same forwards and backwards.

For `race, car, ecar, a, ra` the pairs include race + car ("racecar"), race + ecar, ecar + race, a + ra ("ara") and ra + car ("racar").

## The key question

> **When x + w is a palindrome, what must be true of the two words?**

Line the joined string up with its reverse. The shorter word must mirror one end of the longer word exactly, and whatever is left of the longer word sits in the middle, so it must read the same both ways on its own.

## Approach 1: Join every ordered pair and check it

For every ordered pair of words, join them and check whether the result reads the same backwards.

<Viz client:visible approach="pairs" />

<Complexity time="O(n² · L)" space="O(L)">
**Time.** n(n − 1) ordered pairs, each checked in O(L): **O(n² · L)**.

**Space.** One joined string at a time: **O(L)**.

**What it wastes:** checking pairs whose ends can't possibly mirror each other.
</Complexity>

## Approach 2: Split each word, look up the reversed rest (optimal)

Map every word, reversed, to its position. Cut each word w into left and right at every point. If left reads the same both ways and right reversed is some word j, then words[j] + w works. If right reads the same both ways and left reversed is some word j, then w + words[j] works.

<Viz client:visible approach="split" />

<Complexity time="O(n · L²)" space="O(n · L)">
**Time.** Each word has L + 1 cuts, each with an O(L) palindrome check and lookup: **O(n · L²)**.

**Space.** The map of reversed words: **O(n · L)**.
</Complexity>

Race two approaches on the same input. Both share one clock that ticks once per operation, so the one doing extra work visibly falls behind.

## Common mistakes

- **Counting a pair twice when one side is empty.** The cut with the whole word on the left and nothing on the right finds the same pair as the opposite cut; skip one of them (here, k < length(w) on the second check).
- **Pairing a word with itself.** j ≠ i, even when a word is its own reverse.
- **Only checking one order.** "race" + "ecar" and "ecar" + "race" are different pairs.
