## The problem

You get the `root` of a binary tree. Return `true` if it's a valid **binary search tree**: for every node, *all*
values in its left subtree are smaller than it and *all* values in its right subtree are bigger.

`[8, 3, 10, 1, 6, null, 14, null, null, 4, 9]` is **not** valid, even though every node is in the right place
relative to its own parent: `9` sits under `6` (fine) but inside `8`'s left subtree, and `9 > 8`.

## The key question

> **What does a node need to know that its parent alone can't tell it?**

The limits set by *all* its ancestors. Checking each node only against its children misses cases like the `9`
above. Every correct approach carries more context than that.

## Approach 1: Check every subtree against every node

The definition, taken literally: at each node, read its whole left subtree and its whole right subtree and check
every value. In the example it fails straight away at the root, because `9` is in `8`'s left subtree.

<Viz client:visible approach="brute" />

<Complexity time="O(n · h)" space="O(h)">
**Time.** Every value is re-read once for each of its ancestors: up to `n · h` reads, **O(n²)** for a chain.

**Space.** Recursion depth: **O(h)**.

**What it wastes:** the same values are checked again at every level above them.
</Complexity>

## Approach 2: In-order traversal must increase

An in-order walk (left subtree, node, right subtree) of a BST visits the values in increasing order. So walk in
order and check that each value beats the one before it. The `#` labels show the visiting order.

<Viz client:visible approach="inorder" />

<Complexity time="O(n)" space="O(h)">
**Time.** Each node is visited once: **O(n)**.

**Space.** Recursion depth: **O(h)**, plus one variable for the previous value.
</Complexity>

## Approach 3: Pass down allowed ranges (optimal)

Give each node the range its value must fall in. The root allows anything. Going left caps the maximum at the
parent's value; going right raises the minimum to it. Each node checks only its own range, shown under it.

<Viz client:visible approach="bounds" />

<Complexity time="O(n)" space="O(h)">
**Time.** One O(1) check per node: **O(n)**, stopping at the first node outside its range.

**Space.** Recursion depth: **O(h)**.
</Complexity>

## Common mistakes

- **Comparing a node only with its children.** The example above passes that check and still isn't a BST.
- **Allowing equal values.** Here a BST needs strictly smaller on the left and strictly bigger on the right, so `[2, 2]` is invalid.
- **Using the smallest possible integer as a starting bound.** A node may hold exactly that value; use infinity or `none`.
