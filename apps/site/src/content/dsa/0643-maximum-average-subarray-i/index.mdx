## The problem

You get a list of numbers `nums` and a length `k`. Among all stretches of exactly `k` neighbouring values, find the
largest average, and return it.

For example, in `[3, −2, 6, 1, −4, 8, 2]` with `k = 3`, the stretch `−4, 8, 2` has the largest total, 6, so the answer is
an average of 2. Since every window has the same length, the largest average is just the largest total divided by `k`.

## The key question

> **When the window moves one place right, how much of its total actually changes?**

See [Sliding window](/concepts/sliding-window/): only one value enters and one leaves.

## Approach 1: Add up every window from scratch

For each starting position, add up the next `k` values.

<Viz client:visible approach="recompute" />

<Complexity time="O(n · k)" space="O(1)">
**Time.** `n − k + 1` windows, `k` additions each: **O(n · k)**.

**Space.** **O(1)**.

**What it wastes:** each window repeats `k − 1` of the additions the previous one already did.
</Complexity>

## Approach 2: Slide a running sum (optimal)

Add up the first window. Then for each next position, add the value entering on the right and subtract the one leaving
on the left, and keep the best total.

<Viz client:visible approach="slide" />

<Complexity time="O(n)" space="O(1)">
**Time.** One addition and one subtraction per step: **O(n)**, whatever `k` is.

**Space.** **O(1)**.
</Complexity>

## Common mistakes

- **Starting the best at 0.** With all-negative numbers every average is negative; start at the first window's total
  (or `−∞`).
- **Dividing inside the loop.** It works, but comparing totals is exact; divide once at the end.
- **Using integer division.** The average can be a fraction: 7 / 2 is 3.5.
