## The problem

You get an array `nums` of `n` whole numbers, each between 1 and `n`. Some values appear twice (or more), so some
values from 1 to `n` don't appear at all. Return the missing ones. Try to use no extra memory besides the answer.

For example, `[4, 2, 2, 6, 1, 4]` has six values, so it should contain 1 to 6. The 2 and the 4 appear twice, and 3
and 5 never appear, so the answer is `[3, 5]`.

## The key question

> **How can I remember which values I've seen, without a set and without extra memory?**

A [hash set](/concepts/how-hash-maps-work/) would do it, but costs O(n) memory. The values themselves are the
clue: every value is a valid position (minus one), so the array has exactly one slot to note down each value.

## Approach 1: Search the array for each value

For each `v` from 1 to `n`, scan the whole array for it.

<Viz client:visible approach="search" />

<Complexity time="O(n²)" space="O(1)">
**Time.** `n` values, each needing a scan of up to `n` positions: **O(n²)**.

**Space.** Nothing extra besides the answer: **O(1)**.

**What it wastes:** it reads the whole array again for every single value.
</Complexity>

## Approach 2: Remember the values in a set

One pass puts every value in a set; then each `v` from 1 to `n` is one lookup.

<Viz client:visible approach="withSet" />

<Complexity time="O(n)" space="O(n)">
**Time.** Two passes with O(1) work per step: **O(n)**.

**Space.** The set holds up to `n` values: **O(n)**.

**What it wastes:** memory for a set, when the array itself has a slot for every possible value.
</Complexity>

## Approach 3: Mark positions in the array itself (optimal)

Value `v` names position `v − 1`. Walk the array, and for each value make the number at its named position negative:
that minus sign means "`v` appears". Values already turned negative by an earlier mark still tell you what they
were: take `abs(x)`. At the end, any position `i` that is still positive was never named, so `i + 1` is missing.
This is the "array as its own notebook" move from [Rewriting an array in
place](/concepts/rewriting-arrays-in-place/).

<Viz client:visible approach="marking" />

<Complexity time="O(n)" space="O(1)">
**Time.** One pass to mark, one to collect: **O(n)**.

**Space.** The marks live in the input itself, so nothing extra besides the answer: **O(1)**. (It does change the
input; you could turn every value positive again afterwards.)
</Complexity>

## Common mistakes

- **Forgetting `abs`.** A value may already have been made negative by an earlier mark; `nums[x − 1]` with a negative
  `x` points outside the array. Always use `abs(x)` to read what was stored.
- **Flipping instead of marking.** `nums[p] ← -nums[p]` turns a mark back off when a value appears twice. Use
  `-abs(nums[p])`, which stays negative.
- **Off by one.** Value `v` lives at position `v − 1`, and position `i` stands for value `i + 1`.
