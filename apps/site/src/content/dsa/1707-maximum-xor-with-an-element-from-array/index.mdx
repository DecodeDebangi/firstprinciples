## The problem

You get a list `nums` and queries `(x, m)`. For each query, return the largest value of `x xor a` over the numbers `a` in `nums` with `a ≤ m`, or −1 if no number is that small.

In the animation, write queries as `x m`. For `nums = 3, 10, 5, 12, 9` and the queries `6 4, 6 9, 1 2`, the answers are 5 (6 xor 3), 15 (6 xor 9) and −1.

## The key question

> **Each query allows a different set of numbers. How can one trie serve them all?**

Answer the queries in order of their limit. Then the allowed set only ever grows: before each query, add the numbers up to its limit, and the trie holds exactly the allowed numbers.

## Approach 1: Check every number for every query

For each query, look at every number at most m and keep the largest x xor a.

<Viz client:visible approach="scan" />

<Complexity time="O(n · q)" space="O(1) extra">
**Time.** Every query checks all n numbers: **O(n · q)**.

**Space.** Nothing beyond the answers: **O(1)** extra.

**What it wastes:** rechecking all the numbers for every query.
</Complexity>

## Approach 2: Sort by the limit, grow a binary trie as it rises (optimal)

Sort the numbers, and order the queries by m. For each query, insert the numbers that are now ≤ m, then walk the binary trie for x, taking the opposite bit where possible. Put each answer back in the query's original place.

<Viz client:visible approach="trie" />

<Complexity time="O((n + q) · B) after sorting" space="O(n · B)">
**Time.** Sorting is O(n log n + q log q). Each number is inserted once and each query walks once, B steps each: **O((n + q) · B)**.

**Space.** The trie: **O(n · B)**.
</Complexity>

## Comparing the approaches

Race two approaches on the same input. Both share one clock that ticks once per operation, so the one doing extra work visibly falls behind.

## Common mistakes

- **Answering queries in the given order.** The trie can't remove numbers, so a smaller limit after a larger one would see too many.
- **Losing the original order.** Sort positions, not the queries themselves, and write each answer to its own position.
- **Walking an empty trie.** If no number is ≤ m yet, the answer is −1.
