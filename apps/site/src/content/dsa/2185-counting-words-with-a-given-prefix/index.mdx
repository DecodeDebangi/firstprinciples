## The problem

You get a list of words and a string `pref`. Return how many of the words start with `pref`.

For the words `cart, care, dog, carp, cat` and `pref = car`, the answer is 3.

## The key question

> **Is a trie worth building for one question?**

No. Building it reads every letter of every word; checking the first p letters of each word reads less. A trie wins only when the same words answer many prefixes.

## Approach 1: Build a counting trie, then read one count

Insert every word into a trie that counts the words passing through each node, then walk the prefix and read the count.

<Viz client:visible approach="trie" />

<Complexity time="O(total letters)" space="O(total letters)">
**Time.** Building reads every letter: **O(total letters)**; the walk is O(p).

**Space.** The trie: **O(total letters)**.

**What it wastes:** building a structure for a single question.
</Complexity>

## Approach 2: Check how each word starts (optimal)

For each word, compare its first letters with the prefix, stopping at the first difference.

<Viz client:visible approach="check" />

<Complexity time="O(n · p)" space="O(1)">
**Time.** At most p letters per word: **O(n · p)**.

**Space.** A counter: **O(1)**.
</Complexity>

## Comparing the approaches

Race two approaches on the same input. Both share one clock that ticks once per operation, so the one doing extra work visibly falls behind.

<Compare client:visible />

| Approach | Time | Space | Idea |
|---|---|---|---|
| Build a counting trie, then read one count | O(total letters) | O(total letters) | Count once, read once |
| Check how each word starts | **O(n · p)** | O(1) | Just compare |

## Common mistakes

- **Counting words that contain the prefix anywhere.** It must be at the start.
- **Comparing the whole word.** Stop after p letters, or at the first difference.
- **Building a trie for one prefix.** It's more work than it saves here.
