## The problem

You get the root of a binary search tree and a number `k`. Return `true` if two different nodes add up to `k`.

For the tree `[8, 3, 10, 1, 6, null, 14, null, null, 4, 7]` and `k = 14`, the answer is `true`: 4 + 10.

## The key question

> **Which faster tool does a BST hand you for a pair-sum question?**

A sorted list, by reading it in order. Then it's [two pointers](/concepts/two-pointers/), as in [Two Sum II](/dsa/two-sum-ii-input-array-is-sorted/).

## Approach 1: For each node, search for its partner

For each value `x`, walk down from the root looking for `k − x`.

<Viz client:visible approach="search" />

<Complexity time="O(n · h)" space="O(h)">
**Time.** Each of the `n` nodes runs a search of up to `h` steps: **O(n · h)**.

**Space.** A pointer and the walk: **O(h)**.

**What it wastes:** every search starts again from the root.
</Complexity>

## Approach 2: In-order list, then two pointers (optimal)

Read the values in order into a sorted list. Start `lo` at the smallest and `hi` at the largest; if the sum is too small, move `lo` up; too big, move `hi` down.

<Viz client:visible approach="pointers" />

<Complexity time="O(n)" space="O(n)">
**Time.** One read and one pass: **O(n)**.

**Space.** The list: **O(n)**. (A hash set of values seen is also O(n), and works on any tree.)
</Complexity>

## Comparing the approaches

Race two approaches on the same input. Both share one clock that ticks once per operation, so the one doing extra work visibly falls behind.

<Compare client:visible />

| Approach | Time | Space | Idea |
|---|---|---|---|
| For each node, search for its partner | O(n · h) | O(h) | One search per node |
| In-order list, then two pointers | **O(n)** | O(n) | Sorted list + two pointers |

## Common mistakes

- **Using the same node twice.** For `k = 8` and a node 4, 4 + 4 doesn't count unless there are two 4s.
- **Moving the wrong pointer.** Too small means the left value can't pair with anything: move `lo`.
- **Forgetting that a hash set works too.** It's O(n) and doesn't need the BST order at all.
