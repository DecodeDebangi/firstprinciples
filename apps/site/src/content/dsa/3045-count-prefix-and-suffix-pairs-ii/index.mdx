## The problem

You get a list of words. Count the pairs of positions `i < j` where `words[i]` is both a prefix and a suffix of `words[j]` (it starts it and ends it).

For `ab, abab, b, bab, abcab` the answer is 3: "ab" starts and ends both "abab" and "abcab", and "b" starts and ends "bab".

## The key question

> **How can one walk check a word's start and its end at the same time?**

Walk both ends together: step k looks at the k-th letter from the start and the k-th from the end as one key. Then "u starts and ends w" becomes "u's keys are the first keys of w's", an ordinary prefix question.

## Approach 1: Check every earlier word

For each word, check every earlier word: does it start the word, and does it end it?

<Viz client:visible approach="pairs" />

<Complexity time="O(n² · L)" space="O(1) extra">
**Time.** Every pair is compared over up to L letters at each end: **O(n² · L)**.

**Space.** Nothing extra.

**What it wastes:** comparing pairs that differ in their very first letter.
</Complexity>

## Approach 2: A trie of (first, last) letter pairs (optimal)

Go through the words in order. For each, walk a trie keyed by (w[k], w[length − 1 − k]), adding the number of earlier words that end at each node passed. Then add 1 at the node where this word ends.

<Viz client:visible approach="trie" />

<Complexity time="O(total letters)" space="O(total letters)">
**Time.** One walk per word, one step per letter: **O(total letters)**.

**Space.** The trie: **O(total letters)**.
</Complexity>

Race two approaches on the same input. Both share one clock that ticks once per operation, so the one doing extra work visibly falls behind.

## Common mistakes

- **Counting pairs in both orders.** Only an earlier word can count for a later one, so insert each word after counting for it.
- **Keying on single letters.** A trie of letters checks only the start; the pairs check both ends at once.
- **Forgetting equal words.** A word starts and ends an identical later word, so it counts.
