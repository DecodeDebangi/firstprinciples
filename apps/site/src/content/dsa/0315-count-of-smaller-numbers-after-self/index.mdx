## The problem

You get a list `nums`. Return a list `out` of the same length, where `out[i]` is how many numbers to the right of position `i` are strictly smaller than `nums[i]`.

For `nums = [4, 9, 2, 7, 2, 5, 1]` the answer is `[3, 5, 1, 3, 1, 1, 0]`. For example, after 7 come 2, 5 and 1, all smaller, so its count is 3.

## The key question

> **If you walk from the right, what does "smaller numbers after me" become?**

"Smaller numbers I've already seen." That's a running count by value: how many seen values have a smaller rank. A Fenwick tree answers that prefix count, and takes each new value, in O(log n).

## Approach 1: Check every later number

For each position, look at every position after it and count the smaller values.

<Viz client:visible approach="brute" />

<Complexity time="O(n²)" space="O(1)">
**Time.** Every pair is compared once: n(n − 1)/2 checks, **O(n²)**.

**Space.** Only the answer list: **O(1)** extra.

**What it wastes:** comparisons repeated across positions. Each number re-scans the same tail the previous one already scanned.
</Complexity>

## Approach 2: Walk right to left, counting with a Fenwick tree (optimal)

Sort the distinct values and give each a rank from 1. Walk from the right. For each number, its answer is how many seen values have a smaller rank: a prefix total in the Fenwick tree. Then add 1 at its own rank.

<Viz client:visible approach="fenwick" />

<Complexity time="O(n log n)" space="O(n)">
**Time.** Sorting is O(n log n), then each number does one prefix and one add of O(log n): **O(n log n)**.

**Space.** The ranks and the tree: **O(n)**.
</Complexity>

## Comparing the approaches

Race two approaches on the same input. Both share one clock that ticks once per operation, so the one doing extra work visibly falls behind.

## Common mistakes

- **Counting equal values as smaller.** Ask for the prefix up to rank − 1, not rank.
- **Walking left to right.** Then the counts describe numbers before each position, not after.
- **Using the values themselves as positions.** Values can be negative or huge; ranks keep the tree as small as the number of distinct values.
