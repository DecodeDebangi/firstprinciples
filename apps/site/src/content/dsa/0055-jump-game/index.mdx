## The problem

You get a list `nums` of non-negative whole numbers. You start at position 0, and from position `i` you may jump forward
any distance from 1 up to `nums[i]`. Return whether you can reach the last position.

For example, `[2, 3, 1, 1, 0, 2, 1]`: from 0 jump to 1, from 1 jump 3 to 4… but 4 holds 0. From 3 you can only reach 4
too, and nothing gets past position 4, so the answer is false. `[2, 3, 1, 1, 4]` would be true.

## The key question

> **Do I need to know the route, or just how far I can possibly get?**

Only how far. See [Greedy in practice](/concepts/greedy-in-practice/): keep the farthest reach.

## Approach 1: Mark every reachable position

Mark position 0. From each marked position, mark every position its jump can land on. The answer is whether the last
position gets marked.

<Viz client:visible approach="mark" />

<Complexity time="O(n²)" space="O(n)">
**Time.** Each position can mark up to `n` others: **O(n²)**.

**Space.** The marks: **O(n)**.

**What it wastes:** the reachable positions always form one unbroken stretch from 0, so a single number, its far end,
says everything the marks do.
</Complexity>

## Approach 2: Keep the farthest reach (optimal)

Walk forward with `far`, the farthest reachable position. At each position `i ≤ far`, update
`far = max(far, i + nums[i])`. If `i` ever passes `far`, you're stuck; if `far` reaches the last position, you're done.

<Viz client:visible approach="reach" />

<Complexity time="O(n)" space="O(1)">
**Time.** One pass: **O(n)**.

**Space.** One number: **O(1)**.
</Complexity>

## Common mistakes

- **Always jumping the full distance.** A shorter jump can land somewhere with a longer jump; the farthest reach covers
  every choice at once.
- **Treating every 0 as a dead end.** A 0 only matters if nothing before it can jump over it.
- **Forgetting a one-element list.** You're already at the last position: true.
