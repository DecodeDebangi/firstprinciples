## The problem

You get a list of integers `nums`, which may include negatives. Return the largest sum of any non-empty
**contiguous** subarray.

For `nums = [4, -7, 3, -1, 5, -9]` the answer is `7`: `3 + (−1) + 5`.

## The key question

> **If I know the best sum of a run ending at the previous number, what's the best run ending here?**

Either that run extended by this number, or this number alone. You only start fresh when the run so far is
negative, because a negative prefix can only make what follows smaller.

## Approach 1: Brute force, every subarray

Try every start `i`, and extend the end `j` one step at a time with a running total, so each subarray costs one
addition.

<Viz client:visible approach="brute" />

<Complexity time="O(n²)" space="O(1)">
**Time.** `n(n + 1)/2` (start, end) pairs: **O(n²)**. Without the running total, summing each subarray from
scratch would be O(n³).

**Space.** A few numbers: **O(1)**.

**What it wastes:** for each new start it re-adds the same numbers, even though the best run ending at each
position can be carried forward.
</Complexity>

## Approach 2: Kadane's algorithm (optimal)

Keep `cur`, the best sum of a run ending at the current number, and `best`, the best seen anywhere. At each number
`x`: `cur ← max(x, cur + x)`, then `best ← max(best, cur)`. The shelf shows the current run; watch it restart
whenever carrying the old run would hurt.

<Viz client:visible approach="kadane" />

<Complexity time="O(n)" space="O(1)">
**Time.** One pass, O(1) per number: **O(n)**.

**Space.** Two numbers, `cur` and `best`: **O(1)**.

This is the simplest example of dynamic programming: each answer (`cur` here) is built from the one before it,
and the greedy choice to drop a negative prefix is always safe.
</Complexity>

## Common mistakes

- **Starting `best` at 0.** If every number is negative, the answer is the largest single number, e.g. `−1` for `[−3, −1, −2]`. Start from `nums[0]`.
- **Resetting to 0 instead of to `x`.** `cur ← max(x, cur + x)` keeps the run non-empty.
- **Updating `best` before `cur`.** Compute the run ending here first, then compare.
