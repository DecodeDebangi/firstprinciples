## The problem

A list holds only the values 0, 1 and 2 (think of three colours). Rearrange it **in place** so all the 0s come first,
then the 1s, then the 2s, without calling a library sort. The follow-up asks for a single pass with O(1) extra space.

For `[2, 0, 1, 2, 1, 0, 0, 2]` the result is `[0, 0, 0, 1, 1, 2, 2, 2]`.

## The key question

> **With only three possible values, I don't need comparisons between items at all. Can I put each value in its
> group the moment I see it?**

## Approach 1: Count, then overwrite

Count the 0s, 1s and 2s in one pass, then overwrite the list: that many 0s, then 1s, then 2s. This is counting sort
with only three values.

<Viz client:visible approach="count" />

<Complexity time="O(n)" space="O(1)">
**Time.** One pass to count, one pass to write: **O(n)**.

**Space.** Three counters: **O(1)**.

**What it wastes:** a second pass. It also only works because the values are plain numbers: if each item were a
record with a colour plus other data, overwriting would lose the data.
</Complexity>

## Approach 2: One-pass three-way partition

Walk the list once with three pointers. Before `lo` is all 0s, from `lo` to `mid` all 1s, after `hi` all 2s, and
`mid` to `hi` is still to check. At each step look at `nums[mid]`: a 0 swaps to the front, a 2 swaps to the back,
and a 1 stays where it is. This is the partition from [Sorting as a tool](/concepts/sorting-as-a-tool/), with 1 as
the pivot. It's often called the **Dutch national flag** problem, after the flag's three stripes.

<Viz client:visible approach="flag" />

<Complexity time="O(n)" space="O(1)">
**Time.** Every step either moves `mid` forward or `hi` back, so the gap between them shrinks by one each time:
at most n steps, **O(n)**.

**Space.** Three pointers: **O(1)**.

**What it wastes:** nothing. One pass, no extra memory, and it moves whole items, so it works for records too.
</Complexity>

## Comparing the approaches

Step through both side by side. Both share one clock that ticks once per operation.

<Compare client:visible />

| Approach | Time | Extra space | Passes |
|---|---|---|---|
| Count and overwrite | O(n) | O(1) | 2 |
| Three-way partition | O(n) | O(1) | **1** |

Both are O(n), so there's no growth chart: the lines would differ only by a constant factor.

## Common mistakes

- **Moving `mid` after swapping with `hi`.** The value that came from the back hasn't been checked; it could be a 0
  or a 2.
- **Looping while `mid < hi`.** The cell at `hi` itself still needs checking: use `mid ≤ hi`.
- **Calling a library sort.** It works, in O(n log n), but the problem rules it out.
- **Swapping 0s with `mid` but forgetting to move `lo`.** Then the next 0 overwrites the last one's place.
