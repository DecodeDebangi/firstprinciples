## The problem

You get two words `a` and `b`. In one edit you can insert a letter, delete a letter, or replace one letter with
another. Return the fewest edits that turn `a` into `b`.

For example, `cat` becomes `cut` in 1 edit (replace `a` with `u`), and `kitten` becomes `sitting` in 3 (replace `k`
with `s`, replace `e` with `i`, insert `g`).

Below, `m` and `n` are the lengths of `a` and `b`.

## The key question

> **What could the very last edit have been, and what's left to solve after it?**

See [DP on two strings](/concepts/dp-on-two-strings/): the same table as the longest common subsequence, with a
different rule.

## Approach 1: Plain recursion

`ed(i, j)` is the fewest edits from the first `i` letters of `a` to the first `j` of `b`. If one side is empty, it's
`i + j` deletes or inserts. If the last letters match, they need nothing: `ed(i − 1, j − 1)`. Otherwise try all three
edits: replace (`ed(i − 1, j − 1)`), delete `a`'s letter (`ed(i − 1, j)`) or insert `b`'s letter (`ed(i, j − 1)`), and
add one to the cheapest.

<Viz client:visible approach="recursion" />

<Complexity time="O(3^(m+n))" space="O(m + n)">
**Time.** Each mismatch branches three ways: exponential, up to about **O(3^(m+n))**.

**Space.** The [call stack](/concepts/recursion/), at most `m + n` deep: **O(m + n)**.

**What it wastes:** there are only `(m + 1)(n + 1)` different pairs `(i, j)`, solved again and again.
</Complexity>

## Approach 2: Fill a table (optimal)

Store `ed(i, j)` in `dp[i][j]`, filled row by row. Row 0 and column 0 are `i + j`. For the rest: on a match, copy the
diagonal; otherwise one plus the smallest of diagonal (replace), above (delete) and left (insert).

<Viz client:visible approach="table" />

<Complexity time="O(m · n)" space="O(m · n)">
**Time.** One constant-time rule per cell: **O(m · n)**.

**Space.** The table: **O(m · n)**. Each row only reads the row above, so two rows give the number in
**O(min(m, n))** space.
</Complexity>

## Common mistakes

- **Starting row 0 and column 0 at 0.** Turning `i` letters into nothing takes `i` deletes.
- **Adding 1 on a match.** Matching letters need no edit; copy the diagonal.
- **Mixing up which neighbour is which edit.** Above (one fewer letter of `a`) is a delete; left (one fewer of `b`) is
  an insert. The count is the same either way, but it matters when you rebuild the list of edits.
