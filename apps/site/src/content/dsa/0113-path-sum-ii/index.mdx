## The problem

You get the root of a binary tree and a number `target`. Return every root-to-leaf path whose values add up to `target`, each as a list of values.

For the tree `[6, 3, 8, 2, 1, null, -3, null, null, 2]` and `target = 11`, the answer is `[6, 3, 2]` and `[6, 8, -3]`.

## The key question

> **What does each call need to carry, and what should only be copied at the end?**

It needs the amount still needed, a single number. The path itself can be one shared list, copied only when a leaf matches. [Path Sum](/dsa/path-sum/) is the same walk with a yes-or-no answer.

## Approach 1: Copy the path at every node

Each call makes a new list: the path so far plus its own value. At a leaf, keep the list if its sum matches.

<Viz client:visible approach="copy" />

<Complexity time="O(n · h)" space="O(n · h)">
**Time.** Each node copies up to `h` values: **O(n · h)**, O(n²) on a chain.

**Space.** The copies along the current path: **O(n · h)** in the worst case.

**What it wastes:** copying paths that will never match, at every node instead of only at matching leaves.
</Complexity>

## Approach 2: One shared path, copied only when it matches (optimal)

Push each node onto one shared list and pass down `remain − node.val`. At a leaf with 0 remaining, copy the list into the answer. Pop the node when its subtrees are done.

<Viz client:visible approach="shared" />

<Complexity time="O(n + k · h)" space="O(h)">
**Time.** Each node is pushed and popped once, and each of the `k` matching paths is copied once: **O(n + k · h)**.

**Space.** The shared path and the recursion: **O(h)**, plus the answer.
</Complexity>

## Comparing the approaches

Race two approaches on the same input. Both share one clock that ticks once per operation, so the one doing extra work visibly falls behind.

<Compare client:visible />

| Approach | Time | Space | Idea |
|---|---|---|---|
| Copy the path at every node | O(n · h) | O(n · h) | A fresh copy per node |
| One shared path, copied only when it matches | **O(n + k · h)** | O(h) | Push, recurse, pop; copy on a match |

## Common mistakes

- **Storing the shared list itself instead of a copy.** It keeps changing; the answer must hold a snapshot.
- **Stopping early when the sum passes the target.** Values can be negative, so the sum can come back down.
- **Checking the sum at nodes that aren't leaves.** The path has to reach a leaf.
