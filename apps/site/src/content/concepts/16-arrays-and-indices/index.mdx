## A row of numbered boxes

An **array** is a list of values kept in a row, like a row of boxes. Each box has a number written on it, its
**index** (its position). Here is an array called `a`:

| index | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| value | 7 | 3 | 9 | 4 | 6 |

- `a[0]` is 7, `a[2]` is 9, `a[4]` is 6.
- `length(a)` is 5: there are five boxes.
- The **first** index is always 0, and the **last** is `length(a) - 1`, here 4.

Why 0 and not 1? The index says how far a box is from the start. The first box is zero steps from the start.
Nearly every language counts this way, so it's worth getting used to now.

**Reading any box is instant.** Asking for `a[3]` doesn't mean walking past boxes 0, 1 and 2. The computer jumps
straight there, however long the array is. That's what makes arrays so useful.

Text works the same way. The word `"code"` is an array of characters: `s[0]` is `"c"` and `s[3]` is `"e"`.

## Grids: arrays of arrays

Some problems give you a grid, like a map or a board. That's an array whose boxes are themselves arrays:
`grid[r][c]` is row `r`, column `c`. Both start at 0, so the top-left corner is `grid[0][0]`.

## Mistakes everyone makes at the edges

- **Going one past the end.** `a[length(a)]` doesn't exist: the last box is `a[length(a) - 1]`. This is called an
  *off-by-one* error, and it's the most common bug in all of programming.
- **Forgetting the empty array.** If `a` has no values, `a[0]` doesn't exist either. Ask what your code does when
  the input is empty.
- **Changing the array while walking it.** Adding or removing boxes in the middle of a loop shifts every index
  after them, so the loop skips or repeats values.
